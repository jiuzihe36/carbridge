## 故意不修（有明确理由，不是遗漏）

| 项 | 理由 |
|---|---|
| AirPlay `features` 声明位（AUDIO_REDUNDANT / HEVC） | 与实现不符属实，但改清单会改变与真车的协商；当前基线已实车验证，动它必须实车回归 |
| `BtIap2Server`「10s 无入向判僵死」 | 判据看似激进，但它服务的正是「车机关蓝牙再开回来」的恢复路径（见 skill 规则 14），改严会破坏该恢复 |
| 引擎写路径整体解耦（write-lock 重排） | 需要「阻塞写 + 并发读」的可复现测试环境才敢动；当前只摘了定时器侧（authTimer 双线程） |
| `WifiJoiner` 主线程 join | 复核结论：sleep 轮询在独立线程（wifi-join-fallback），API 29+ 走 async specifier，目标机（Android 15+）不受影响 |
| `WifiJoiner` joinLegacy（API≤28） | 交付机 Android 15+ 走不到该路径；无老设备可验证 |
| Ed25519 变时 ladder / X25519 变时 | 加固面窄（本地配对流程），实现重写风险大于收益 |
| M2 验签的 `pk` 接线 | 需要真车 mDNS TXT 或 0x4301 参数 4 的现场抓包；当前已做「有钉扎缺签名=失败」的 fail-closed |
| `rememberCarProfile` 的画布预置仅限未采集时 | 车机 /info 上报值优先，避免旧记录覆盖新协商 |

## 无法验证（需要实车）

- pair-verify 换真 AEAD 后对真实车机的回归（车机 tag 合法则无感；失败会自动退匿名 et=1 旧路径）。
- 重配对后的识别（车机侧旧配对缓存清除后的首次配对链路）。
- 「一键解锁」0.1.25+ 的真实判定结果（此前读数不可信）。
